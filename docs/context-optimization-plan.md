# 上下文优化方案（草案）：从「事后清除」转向「准入端选择」

> 状态：方案草案，未动代码。范围限定在 **tool result**（不涉及 thinking/reasoning）。
> 事实基础来自对 DSH 安装目录与 `~/.dsh/sessions` 的只读查证，证据均带路径/行号。

---

## 1. 背景：为什么必须换位置

现有插件（`dsh-clear-tool-results` v0.7.0）在**轮末**（`ctx.on('session/event')` → `turn/end`）把该轮所有 `tool/result` 无条件替换成 ~92 码点占位符。查证后发现两件事：

1. **DSH 内置已经有四套上下文优化机制，且默认全开**（见 §2）。现有插件与其中三套作用于同一对象，但更粗、更早、更频繁。
2. **现有插件使内置机制空转**（见 §3 实测）：内置修剪器的候选对象被它在轮末提前抹掉。

因此继续沿「轮末全清」形态演进没有增量空间。需要转到内置没有覆盖的位置：**工具产出时（准入端）决定什么进入模型上下文**。

### 1.1 明确不做的事

- 不替换 `ctx.compaction`（不做摘要引擎，不碰 LLM 摘要路线）。
- 不处理 thinking/reasoning（虽无内置竞争者，本轮不做）。
- 不再以「省钱」作为论证主轴（缓存经济性论证经复核不成立，见 `project_history.md`）。

## 2. 事实基础：DSH 内置机制盘点

挂载证据：`dsh-base/cordis.patch.yml` + `dsh-agent-presets/presets/standard/agent.cordis.yml:127-156`；本机 `~/.dsh/settings.yaml` 中 `agent-presets.default: standard`。

| # | 机制 | 触发时机 | 对象 | 处置 | 改写原文 | 默认 |
|---|---|---|---|---|---|---|
| 1 | `dsh-output-retention` | 工具**产出时** | glob/grep/bash/web_fetch/web_search；**`read` 排除** | 按 `maxItems`/`maxBytes` 截断丢弃，附 `Omitted N items.` | 否 | 库，随工具 |
| 2 | `dsh-spill-policy` | **`tools/post-execute` waterfall** | >`maxInlineBytes` 的**纯文本**结果；跳过 `read`、非 text block、嵌套调用 | 全文落盘，模型见有界预览 + `Full formatted result stored at: <path>. …` | 否 | 是（base `maxInlineBytes=50000`） |
| 3 | `dsh-compaction-tool-result-pruner` | **仅 compaction 触发后** | surface 上的 `tool/result` | head + `[... tool result middle pruned ...]` + tail（8192/4096/1024 码点） | 否 | 是 |
| 4 | `dsh-compaction-basic` | `agent/pre-step` 压力 / `request-error` 溢出 / 手动 | 整段最老平衡 span | LLM 摘要替换 | **是** | 是（`thresholdRatio=0.8`→800k token，`retainRatio=0.16`，`auto=true`） |
| 5 | `dsh-command-compact` | 手动 `/compact` | 同 4 | 委托 4 | — | 是 |

共同点：原文全部保留在 append-only 会话日志中，替换事件以 `sourceEventSeqs` 引用原文，可回放。

### 2.1 插件可用的一等扩展点（可行性结论）

```
'tools/post-execute'(exec: ToolExecution, result: Readonly<ToolExecutionResult>,
                     next: () => Promise<PostToolDecision>): Promise<PostToolDecision>
```
- 定义：`dsh-tools/lib/types/index.d.ts:61`；调用点：`dsh-tools/lib/index.js:3378`。
- 返回 `{ kind: 'accept', content: [...] }` 可**替换模型可见内容**（准入端改写的正规入口）。
- 约束：不可同时替换 `value`；失败结果不可替换 `value`（`lib/index.js:3389`、`:3392`）。
- `dsh-spill-policy` 即以此实现，且示范了组合方式：先 `await next()`，再对有界投影做替换（`dsh-spill-policy/lib/index.js:155-171`）；文件头注释明确「它与其他 post-execute 监听器组合」（同文件 `:62-64`）。
- 另有 `tools/ptc-dispatch-log`，约束 `run_code` 子调用写进**日志**的那份副本（不影响程序拿到的值）。
- `ctx.compaction` 每个 context 只能有一个实现（继承 `CompactionEngine`，`dsh-compaction/lib/types/index.d.ts:73`）；pruner 由 compaction-basic 以服务名 `ctx.get("toolResultPruner")` 调用。

**结论：准入端改写技术可行，无需修改 DSH 核心。**

## 4. 问题定义与目标

### 4.1 待解决问题

现有的「清除」发生在信息生命的**末端**；文献与本机内置机制都指向同一结论 —— 有效性取决于**准入端**（数据要不要进来）与**选择质量**（进来后保留哪部分）。内置留白恰好在这两点：

1. **8K~50K 档无人管**：spill 只管 >50KB，pruner 只在压缩时且已被本插件架空。而这一档正是大结果主体（p90~p99）。
2. **`read` 被 spill 显式排除**（防 `read→spill→read` 循环），但 `read` 是一次性数据的主力来源。
3. **语义判断空缺**，且官方自认：pruner 的 README 写明「剪枝只基于语法……不解释中间哪些行在语义上重要」，开发备注「语义化中间选择，**尚未决定**……两者都未随附」。
4. **没有反馈环**：内置三套机制的预算/阈值全是静态硬编码，没有任何机制统计「这一类结果到底会不会被再用」。

### 4.2 目标（可测）

- **主目标**：降低「进入模型上下文、且此后未被复引的 tool result 字节数」。
- **副目标**：不增加模型达成同一任务所需的步数 / 取回次数（即不以信息损失换指标）。
- **护栏**：任务解出率不下降（需对照实验，见 §7）。

### 4.3 非目标

不追求 token 费用最小化；不做摘要式改写；不引入模型调用（除方案丙的可选分支）。

## 5. 三个候选方案

### 方案甲：复引率反馈（度量先行）

**做什么**：先建立「结果是否被再次需要」的度量与真值，用它去定乙/丙的参数，而不是猜。

**度量口径**（需在文档评审时定稿）：

| 口径 | 定义 | 可得性 |
|---|---|---|
| A1 直接复引 | 该结果被清除后，`read_tool_result_log` 取回其所属轮 | 仅插件 ON 会话可得（**选择性偏差**：只有被清除的内容才可能被取回） |
| A2 重跑代理 | 同一工具以相同/近似参数在后续被重新调用 | ON/OFF 均可观测（间接证据：说明模型未保留该信息） |
| A3 片段再现 | 该结果的关键片段出现在后续请求 prompt 中 | **不可得**：会话日志不落完整 prompt，需重建，成本高、精度可疑 |
| A4 一次性率 | 所属轮结束后既无 A1 也无 A2 | 可算 |

**输出**：按 `(工具名 × 结果码点分档 × 会话内位置分档)` 的复引率/一次性率表；以及阈值敏感度。

**与内置的关系**：不占用任何内置位置；产出的是**参数与判据**，可用于乙/丙，也可作为对内置 pruner/spill 配置的建议（不改内置）。

**验证标准**：
1. 复现 `a293efee` 的 90.2%；
2. 在 ≥20 个会话上给出稳定分档表（同一档在不同会话间结论一致）；
3. 阈值 ±1 档时结论不翻转。

**已知局限**：A1 只在插件 ON 会话可用；样本需要累积；A2 需要工具参数指纹（`tool/call` 的 `arguments`）。

### 方案乙：中间档准入（收据化）

**做什么**：在 `tools/post-execute` 上，对**内置未覆盖**的档位做按需收据化，与 spill-policy 分工而非重复。

**覆盖范围（按优先级）**：
1. **8K~50K 档的纯文本结果**（spill 因阈值不覆盖，pruner 因时机不覆盖）；
2. **`read` 的结果**（spill 显式跳过）——需谨慎，避免 `read→收据→再 read` 循环，可考虑只对超阈值 `read` 生效并对同一路径加去重；**（2026-09-28 已决：`read` 暂不纳入覆盖，见 §9；若将来纳入，「按路径去重」是硬约束且尚未实现。）**
3. 非 text block 结果**跳过**（与 spill 一致，不做截断）。

**行为**：超出阈值 → 模型侧保留「有界头尾 + 大小 + 定位（路径/轮次）+ 取回指引」；全文落盘——优先复用 `ctx.spillStore`（`dsh-spill-local` 已默认挂载），避免再造一套归档与取回工具。**（2026-09-28 实现改为自建归档**：插件自写 `tool-result-logs/results/*.txt` + `index.json`，不复用 `ctx.spillStore`；取回走现成的 `read`/`grep`，`read_tool_result_log` 保留为按轮/步/时间的入口。**）**

**组合与幂等**：
- 以 `await next()` 之后处理的方式注册，与 spill-policy 同构；
- **必须先验证监听器顺序**（谁在外层），并保证：已是收据形态的结果不再处理（幂等），且不与 spill 重复替换同一结果；
- best-effort：落盘失败、无 session owner 等情况一律保留原结果（沿用 spill 的失败原则，`dsh-spill-policy/lib/index.js:58-60`）。

**验证标准**：
1. dry-run 报告的替换集合与 spill 的替换集合**零重叠**；
2. 对 `read` 有覆盖且不产生读取循环（观察同一路径重复读取次数）；
3. 幂等：二次运行替换集合为空；
4. 影子模式（只记录不替换）下，与内置行为无冲突日志。

### 方案丙：语义化中间选择

**做什么**：做官方明确留白的那一项 —— 判断大结果中间哪些行重要，而不是盲目保留头尾。

**候选做法（由轻到重）**：
1. **结构化启发式**：按行分类（错误行、断言失败、匹配命中、表头、重复行），保留首尾 + 命中行 + 去重后的唯一行；
2. **参数由甲的实测真值拟合**（哪类行真的被后续用到）；
3. **模型判定**（可选，成本高）：仅在超大结果上使用，需缓存与批量。

**验证标准**：在固定任务集上，比较「保留头尾」vs「语义保留」的**重取率**（A1/A2）与步数；语义保留应在同等保留预算下降低重取率。

### 前置策略（非并列候选）：主动落盘（Agent 自管上下文）

**与甲/乙/丙的关系**：甲乙丙**由宿主执行**（被动，在数据已经产生之后决定去留）；丁**由模型执行**（主动，在数据产生之时决定是否进入上下文）。丁不是并列选项，而是**前置项**：它一旦生效，下游三层机制会自动让路 —— 命令自己把输出重定向到文件后，tool result 变小，内置 `spill`（>50000 字节）不触发、内置 `pruner`（>8192 码点）不触发、本插件也无事可做。**用模型的语义知识替代宿主的盲猜。**

**三种落盘形态（关键区分，成本差一个数量级）**：

| 形态 | 机制 | 搬运成本 | 适用 |
|---|---|---|---|
| **产出时重定向**（推荐） | `cmd > /tmp/x.log 2>&1; echo exit=$?; wc -l < /tmp/x.log` | **零**：内容从未经过模型 | 大 grep、长日志、大 diff、批量输出 |
| 事后抄写 | 模型把已读到的内容写进文件 | **最高**：须逐 token 输出一遍，且可能改写失真 | 仅当内容要跨多轮反复使用且必须保真 |
| 结论笔记 | 模型写自己的分析结论 | 低 | 跨压缩存活（对应 Anthropic 的 structured note-taking） |

**命令模板（产出时重定向）**：
```
<原命令> > <artifact>.log 2>&1; echo "exit=$?"; wc -l < <artifact>.log; grep -c -iE 'error|failed|panic' <artifact>.log
```
模型只看到退出码、行数、错误计数、路径；需要细节时用 `head`/`tail`/`grep`/`sed` 渐进式查看。

**三个护栏（缺一个就会伤质量）**：
1. **收据必须由工具产生，不能由模型声明**。「已写入 X」若出自模型之口，可能是幻觉；让 `wc -l` / `ls -l` 的输出作为可验证收据。
2. **落盘必须回显判据**（退出码 + 错误计数 + 行数）。把 stderr 一起重定向却只看 `exit=0`，等于把错误**存起来**而非**处理掉** —— 与 Governance Decay 同源（约束/错误移出视野后违规率 0% → 30%）。
3. **需要可枚举的命名约定 + 产物清单**（如 `.dsh-artifacts/<turn>-<tool>-<slug>.log`）。「上下文只留一句话」在压缩/跨轮后会消失，而**约定可枚举**（`ls`），记忆不可枚举。

**实测现状（本机 77 会话 / 1,152 次 bash）**：重定向到 `/dev/null`（丢弃）366 次；重定向到真实路径（保存）89 次 / 89 个路径 / 仅 7 个会话，且几乎全是 `/tmp/*.mjs`（**写脚本再执行**，不是卸载数据）；真正的「结果落盘」仅 2~3 例；`tee` 1 次；`write` 工具 27 次。⇒ **该策略是本机空白**，模型会用文件系统但没把它当上下文卸载器。

**制度化钩子（均已查证，无需改 DSH 核心）**：
1. **写进 `AGENTS.md`** —— `dsh-agent-instructions` 默认启用并从全局/项目级 `AGENTS.md` 注入工作区指引。**零成本起步，一行约定即可。**
2. **插件注入系统提示**：`'system-prompt/assemble'(assembly, context, next) => PromptAssembly`（`dsh-system-prompt/lib/types/index.d.ts:27`，调用点 `lib/index.js:351`；`dsh-session-reference` 即以此注入）。适合随插件分发、对所有工作区生效。
3. **`tools/post-execute` 兜底**：命令忘了重定向、结果仍然很大时，再由宿主收据化（即方案乙）。

**与宿主卸载的分工**：

| 对象 | 策略 |
|---|---|
| 大块机器输出、尚未进入上下文 | **命令直接重定向落盘**（主动，零搬运） |
| 已进上下文、跨轮不再需要 | **宿主收据化**（被动，补位） |
| 错误 / 失败 / 约束 / 中间结论 | **都不动**（负知识必须留在视野里） |

**验证标准**：
1. 约定生效后，「真实落盘（非 /dev/null、非脚本文件）」的调用数显著上升，且落盘路径能被后续 `head/tail/grep` 取回；
2. 落盘的命令 100% 带判据回显（退出码 + 错误计数）；
3. 同一批任务上，进入上下文的一次性 tool result 字节数下降，步数与取回次数不上升、解出率不下降。

## 7. 成功标准与评测

- **主指标**：单位任务「未被复引的 tool result 字节数」。
- **副指标**：任务步数、工具调用次数、取回次数（不得上升）。
- **护栏指标**：任务解出率（需对照：{插件 OFF, 影子, 替换} × 同一批任务）。
- 评测必须**对照**才有质量结论；只报 token 变化不构成质量证据。

## 7.5 已知缺陷（本机实测）：三处阈值各写各的，出现两条缝

> **【已作废 · 2026-09-28】** 本节针对 `ARCHIVE_MAX_BYTES = 49000`（本插件归档上限）与 spill `maxInlineBytes = 50000`、`RENDER_BUDGET_BYTES = 48000` 三者的错位。**0.8.0 已删除归档上限**，改为插件自写 `tool-result-logs/results/*.txt`（不受 harness 50000 字节截断影响）⇒ **缝 1 `(49000, 50000]` 永久取不回、缝 2 `(48000, 49000]` 归档但默认跳过均已不存在**。本节仅作历史留档，请勿据此设计；文末「乙必须先解决缝 1」的前置项一并作废。

三条线都是字节口径，但互不对齐：

| 线 | 值 | 判据 | 位置 |
|---|---|---|---|
| 上游截断 / spill 触发 | 50000 | spill 判据是 `totalBytes > 50000`（**严格大于**）；实测所有结果被截到 ≤50000 | `dsh-spill-policy`（base `maxInlineBytes=50000`） |
| 插件归档上限 | 49000 | `archived = bytes <= 49000` | 本插件（旧实现，0.7.0） |
| 插件单次渲染预算 | 48000 | 某条 block 使 `used` 超预算 ⇒ **整条跳过**（`continue`） | 本插件（旧实现，0.7.0） |

| 缝 | 范围 | 后果 |
|---|---|---|
| **缝 1** | (49000, 50000] | **永久取不回**：入不了归档，也触发不了 spill；占位符只提示「未保存原文，如需请重新执行原工具获取」（0.7.0 实现） |
| **缝 2** | (48000, 49000] | 已归档但**默认取不回**：整条被 `continue` 跳过；必须显式传小 `limit` 按行分段 |

**实测**（77 会话 / 3,277 条原始结果，文本 UTF-8 字节）：≤8192 → 2,868 条；8193~49000 → 368 条；**49001~50000 → 41 条**；>50000 → **0 条**。最大值恰为 **50,000 字节** ⇒ **spill 从未触发过**，「harness 落盘兜底」这一假设在本机不成立。

实际写出「未归档」占位符 = **5 条**：`2e8a6107` turn1 · 49,801 B；`a8e95269` turn1 · 49,501 B 与 49,999 B；`a293efee` turn3 · 49,999 B 与 834 B。

**成因**：三处阈值由三个不同位置各自声明（上游 harness / 本插件归档 / 本插件渲染），没有任何一处做一致性校验。

**修复选项（按侵入性排序）**：
1. **对齐数字**：归档上限 ≥ 上游截断线，渲染预算 ≥ 归档上限；
2. **超限不删**：取不回的条目**保留原文在上下文**，只清可归档的（口径：既然取不回，就不该清）；
3. **超限落盘**：写进 `ctx.spillStore`，而不是提示「重新执行原工具」（对日志、时间戳类命令，重跑不可复现）。

**对方案乙的影响**：乙要「复用 `ctx.spillStore`」，**必须先解决缝 1** —— 否则乙会在自己的阈值上复制同一个缺陷。因此推进路线第 1 步前置一项「对齐阈值」。
